# Plans

Store project plans in this folder.

## Suggested Naming

- `001-project-direction.md`
- `002-architecture.md`
- `003-mvp-scope.md`
- `004-demo-script.md`

Use a date prefix instead when a plan is time-sensitive: `YYYY-MM-DD-<slug>.md`.

## Plan Template

Each plan should include:

- Status: proposed, active, blocked, or complete
- Owner
- Goal and non-goals
- User workflow
- Scope and milestones
- Local/offline behavior
- Cloud-dependent behavior and sync rules
- Risks and unresolved decisions
- Acceptance criteria
- Verification commands or manual test steps

Keep plans implementation-ready but avoid locking in a framework or provider before the decision is recorded.
